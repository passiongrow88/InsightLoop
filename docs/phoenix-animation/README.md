# InsightLoop 火凤凰 2.5D 分层动画设计规范

> 本文档是火凤凰网页动画的唯一实现规范。官方角色设定图是唯一美术标准。禁止使用 CSS、SVG 或其他方式重新绘制角色形状；所有角色部件必须直接来自批准后的透明 PNG 素材。

## 目标

把现有火凤凰角色设计在网页中做成忠于原图的 2.5D 分层动画。第一阶段必须完成：

- 待机呼吸
- 自然眨眼
- 尾羽飘动
- 视线跟随鼠标或触控位置
- 点击时的开心反应

第一阶段可使用 Canvas、three.js 纹理平面、PixiJS 或同等级 2D/WebGL 渲染方式，不依赖 Rive。若 2.5D 仍达不到最终要求，再接入外部制作的 Blender、Rive 或其他真 3D 资产。

---

# 一、统一导出规范

- 主装配画布：`2000 × 2000 px`
- 建议角色高度：约 `1500–1650 px`
- 格式：透明背景 PNG
- 色彩：sRGB
- 分辨率：最终网页显示尺寸的 2–4 倍
- 不保留背景、桌面和整体投影
- 阴影、光晕、星光必须单独导出
- 每个部件保留约 `20–40 px` 透明边距，避免旋转时裁切
- 被其他部件遮挡的区域也必须完整，例如翅膀根部和尾羽根部
- 左右命名全部以屏幕视觉方向为准：`screen_left`、`screen_right`
- 锚点使用百分比坐标：左上角为 `0%,0%`，中心为 `50%,50%`
- 图层编号越大，显示越靠前
- 所有锚点先作为设计初始值，最终以 `phoenix_assembly_reference.png` 校准

必须同时提供：

- `phoenix_assembly_reference.png`
- 尺寸：`2000 × 2000 px`
- 内容：展示全部部件正确组合位置，供程序校准

# 四、第一阶段动作设计参数

详细数值见 `MOTION_BLUEPRINT.md`。以下为验收底线：

## 待机呼吸

- 身体缩放幅度不得超过 2.4%
- 头部垂直位移不得超过角色高度的 0.8%
- 头部必须比身体晚 80–140 ms
- 左右翅膀与尾羽不能完全同步

## 自然眨眼

- 普通眨眼间隔随机 2.8–6.5 秒
- 偶尔双眨，概率约 12%
- 闭眼停留 70–110 ms
- 开心状态使用官方开心眼，不通过压扁开放眼代替

## 尾羽飘动

- 五组尾羽使用不同周期
- 建议周期范围 2.4–4.2 秒
- 最大旋转范围 1.5°–4.5°
- 中央尾羽幅度最小，外侧尾羽幅度较大

## 视线跟随

- 仅移动瞳孔，不移动整张眼睛
- 瞳孔位移必须受 clip 遮罩限制
- 最大水平位移建议为眼睛宽度的 7%–11%
- 最大垂直位移建议为眼睛高度的 5%–8%
- 鼠标离开后 220–380 ms 回到中性位置

## 点击开心反应

- 总时长约 900–1300 ms
- 身体先下压 80–120 ms，再向上弹起
- 翅膀展开使用官方开心姿势或官方翅膀部件
- 切换开心眼和开心嘴型
- 星光只做辅助，不遮挡脸部
- 动作结束后平滑回到 idle，不突然跳帧

# 五、硬性禁止事项

- 禁止使用 SVG 重新画火凤凰
- 禁止使用 CSS 圆形、路径或渐变拼出替代角色
- 禁止改变官方头身比例、眼型、嘴型、羽冠形状或尾羽结构
- 禁止用 Emoji 或占位符冒充角色动画
- 禁止把整只角色做成单张 PNG 上下浮动后称为分层动画
- 禁止在没有真实素材的情况下宣称动画完成
- 禁止用 AI 重新生成“相似火凤凰”替代官方资产

# 七、交付验收

素材包只有同时满足以下条件才视为可进入开发：

- 所有第一阶段必需部件为透明 PNG
- `phoenix_assembly_reference.png` 已提供
- 头、身体、双翅、五组尾羽已独立
- 眼睛底层、瞳孔、遮罩、闭眼和开心眼已提供
- 所有部件可在 2000×2000 画布中无缝复原官方待机姿势
- 遮挡区域完整，没有缺口
- 所有文件使用 screen_left / screen_right 命名
- 未混入背景或整体阴影
- PNG 边缘没有白边、黑边或压缩污染
- 角色组合后与官方设定图在比例、颜色、材质和气质上保持一致
