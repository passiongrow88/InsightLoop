# InsightLoop V5 Agent Entry Rules

Before changing code, read in this order:

1. `docs/v5/V5_PRODUCT_CONSTITUTION.md`
2. `docs/v5/V5_POD.md`
3. `docs/v5/V5_TECHNICAL_GUARDRAILS.md`
4. `docs/v5/V5_ACCEPTANCE_TESTS.md`
5. `docs/v5/V5_DECISION_LOG.md`
6. `docs/v5/V5_UNIFIED_VIBE_PROMPT.md`

## Authority

Latest founder-approved `LOCKED` Decision Log entry > Constitution > POD > Technical Guardrails > Acceptance Tests > existing implementation.

## Permanent rules

- Do not redesign InsightLoop V5 from assumptions.
- Do not replace the warm 2.5D study with a dashboard, login wall, chat page, or feature-card grid.
- The journal preserves original user words on the left page and shows the InsightLoop response on the right page.
- InsightLoop owns the journal response. The companion beast is the diary administrator and archive guide.
- The ship’s wheel holds user-confirmed direction, action, and outcome. It is not manifestation.
- The dreamcatcher is a dream archive, not prophecy.
- One related dated record is an echo only. A pattern requires at least two different dated structurally similar records with validated evidence.
- Never expose internal speculation about the user’s hidden motive, aggression, defence, avoidance, resistance, or testing behaviour.
- When blocked, solve the actual technical problem without removing, hiding, faking, replacing, or downgrading the confirmed requirement.
- Do not modify `main`, `insightloop.lol`, production data, auth, keys, migrations, or entitlements without explicit founder approval.
- Work on an approved V5 Preview branch and preserve rollback.
- A successful build or HTTP 200 is not proof of completion.

## Required completion report

Provide:

- branch and commit SHA;
- files changed;
- Preview deployment ID/URL if deployed;
- acceptance-test IDs run and evidence;
- `VERIFIED`, `PARTIALLY VERIFIED`, `BLOCKED`, or `UNKNOWN` status;
- remaining unverified items;
- confirmation that main and production were not changed.
